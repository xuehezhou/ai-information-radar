# AI 信息雷达项目总览

> 文档状态：规划基线 1.0｜基于当前源码 v1.15｜2026-08-20

## 1. 产品定义

AI 信息雷达是一款面向 AI 应用从业者的本地优先信息决策工具。

它不是把新闻简单堆在一起，而是把公开信息经过采集、日期隔离、去重、重要性初筛和 AI 编辑，转化为两类可阅读结果：

- `today_realtime`：今天仍在变化的实时信息池。
- `daily_report`：自然日结束后生成并稳定保存的最终日报。

当前产品形态是 Python + Flask 的桌面源码应用，数据主要保存在本地 JSON 和 Markdown 文件中，并保留历史日报、已读状态和手机同步 API。

## 2. 它解决什么问题

AI 行业信息具有四个典型问题：

1. 数量过多：同一事件会被多个媒体和社区重复报道。
2. 更新过快：只在早上抓一次会漏掉下午和晚上的重大事件。
3. 价值难判断：热度高不代表对 AI 应用开发者有价值。
4. 事实与观点混杂：新闻事实、社区传闻和 AI 推断容易被当成同一种内容。

AI 信息雷达通过“全天低成本采集 + 次日统一结算”降低这些问题：

```text
公开信源
  -> 全天采集
  -> 日期隔离
  -> 规则过滤和去重
  -> 高价值候选
  -> AI 分析与编辑
  -> 可追溯日报
```

## 3. 用户为什么需要它

用户每天真正需要的不是“看完所有 AI 新闻”，而是快速回答：

- 昨天 AI 行业发生了什么重要变化？
- 哪些事件会影响我的产品、技术选型或创业方向？
- 哪些只是重复报道或短期噪声？
- 原始来源在哪里，是否值得相信？
- 今天应该进一步研究什么？

本产品希望把数小时的信息浏览压缩成十几分钟的高质量阅读。

## 4. 目标用户

### 4.1 AI 应用开发者（核心用户）

需要了解模型、API、Agent、工具、开源项目和成本变化，并据此调整开发方案。

### 4.2 AI 产品经理

需要判断行业趋势、竞品变化、用户机会和产品风险，不需要深入阅读每篇技术论文。

### 4.3 AI 创业者和独立开发者

需要从新模型、新工具和工作流中发现可落地的产品机会，并避免被营销信息误导。

### 4.4 普通 AI 关注者

需要用非算法工程师也能理解的语言掌握重要变化，但不是当前第一优先用户。

## 5. 用户痛点、功能和价值

| 用户痛点 | 当前或规划功能 | 用户价值 |
|---|---|---|
| 信息太多 | 规则过滤、候选上限、日报摘要 | 减少阅读负担 |
| 同一事件重复出现 | URL/标题去重，规划中的 Event 聚合 | 一件事只读一次 |
| 容易漏掉晚间信息 | 每 2 小时采集，次日 00:05 结算 | 覆盖完整自然日 |
| 不知道什么重要 | A/B/C 初筛、候选分、AI 编辑 | 重要内容优先 |
| 不知道来源是否可信 | 保存来源、发布时间和原始链接 | 可以回到原文核验 |
| AI 失败导致没内容 | 旧日报降级、状态四态、失败重试 | 系统失败时仍可阅读 |
| 历史日报日期混乱 | `collect_date`、`published_at`、`report_date` 隔离 | 每一期只属于自己的日期 |
| 不知道系统是否正常 | 首页信源健康度、更新状态 | 用户知道当前发生了什么 |

## 6. 与普通新闻聚合器的区别

| 普通新闻聚合器 | AI 信息雷达 |
|---|---|
| 主要按发布时间排列 | 目标是按用户价值和行业影响排序 |
| 多来源文章各自展示 | 规划为多个 Raw News 聚合成一个 Event |
| 当天任何时刻都可能称为“今日日报” | 当天只做实时池，次日才生成完整日报 |
| 强调数量和刷新频率 | 强调重要性、可追溯性和行动价值 |
| 通常只提供摘要 | 还提供为什么重要、对用户的影响和学习建议 |
| 来源状态不可见 | 首页展示信源成功、失败和空结果状态 |

## 7. 核心竞争力

当前最有价值的能力组合是：

1. **自然日完整性**：不是用户打开时临时生成半日报。
2. **低成本分层处理**：采集阶段不用大模型，先用程序规则压缩候选。
3. **面向 AI 应用开发者**：分析重点不是算法论文数量，而是实际开发和创造机会。
4. **本地可控和可追溯**：日报、信息池、状态和日志都在用户电脑上。
5. **失败可恢复**：单个信源或 AI 失败不会破坏历史日报。

当前仍未形成真正壁垒的部分：事件级知识库、跨来源事实验证、稳定可解释的评分和个性化反馈。这些应按路线逐步建设。

## 8. 当前产品边界

### 当前包含

- 9 个公开信源适配器。
- 每 2 小时采集当天信息池。
- 次日 00:05 最终日报结算和有限重试。
- 规则过滤、初筛评分和候选去重。
- OpenAI Responses API 日报生成。
- Flask 首页、详情页、历史日报和已读状态。
- 更新状态接口和手机同步 API。

### 当前不包含

- 用户账号和云端多租户。
- 付费、权限和运营后台。
- 完整的事件实体数据库。
- 自动事实核查 Agent。
- 个性化推荐模型。
- 面向公网的安全部署能力。

## 9. 产品成功指标

在个人桌面阶段，优先使用可验证指标：

| 指标 | 建议目标 |
|---|---|
| 日报按时生成率 | 最近 30 天 >= 95% |
| 关键日期隔离错误 | 0 |
| 历史日报意外覆盖 | 0 |
| 同日重复 AI 任务 | 0 |
| 候选事件原始链接完整率 | 100% |
| 候选事件可解析发布时间比例 | >= 95% |
| 常态信源可用率 | >= 7/9 |
| 日报重要事件人工认可率 | 首阶段 >= 80% |
