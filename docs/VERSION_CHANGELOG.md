# AI 信息雷达版本记录与规划状态

> 本文件连接“已经发生的工程变更”和“未来产品成熟度路线”。历史细节以根目录 `changelog.md` 为准。

## 1. 版本口径

项目目前存在两种编号：

1. 根目录 `changelog.md` 的 v1.0～v1.16：历史工程迭代编号。
2. 规划路线 V0.1～V1.0：从原型到可开源产品的成熟度编号。

为避免误解：

- 当前源码工程编号是 v1.16。
- 当前产品成熟度是 V0.3 已完成、V0.4 部分完成。
- 工程编号较高不代表已经达到产品 V1.0 发布标准。

## 3. 当前状态快照

### 已实现并有测试

- 今天实时池和已完成日报分离。
- 上海自然日和历史日期隔离。
- 全天采集与次日结算。
- 日期任务锁、状态四态和失败保留旧日报。
- 候选相关性、来源配额和规则去重。
- 日报日期、章节和链接质量闸门。
- 首页信源健康状态。
- 首页、详情页、日报 API 和已读状态。

### 部分实现

- 事件去重：有 URL、标题和词元规则，但没有持久化 Event 实体。
- 重要性评分：有 A/B/C 和候选分，但 1～5 星仍由模型自由判断。
- 来源完整性：保存链接，但部分适配器没有可靠发布时间。
- 手机同步：API 和旧 APK 存在，但桌面后续变化尚未形成稳定发布同步流程。

### 尚未实现

- 独立 Raw News、Event、Daily Report 数据契约。
- Research、Editor、Reviewer 三 Agent 工作流。
- 统一 `importance_score` 0～100。
- 调用成本、Token 和质量趋势记录。
- 可复现的开源发布流程。

## 5. 下一版本候选

### 建议工程版本：v1.16

主题：关键信源发布时间完整性。

范围：

- GitHub、Product Hunt、Qwen、DeepSeek 的发布时间提取或明确降级。
- `time_confidence` 概念和数据质量检查。

不包含：Event 全量重构、Prompt 重写、多 Agent 或新 UI。

完成后再进入 V0.4 Event 数据层。

## 7. 发布纪律

- 未运行测试不得标记完成。
- 外部 API 未验证不得标记真实链路通过。
- 历史日报和数据迁移必须说明影响和回滚方式。
- 发布版必须能对应到唯一源码状态。
- API Key、日志、用户数据和本机路径不得进入公开仓库。
