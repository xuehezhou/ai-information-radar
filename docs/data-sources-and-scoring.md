# 信息来源与评分说明

> 本文回答两个核心问题：信息主要来自哪里，以及页面和日报中的等级、星级如何产生。

## 1. 结论先说

当前项目配置了 9 个公开信源，主要覆盖：

- 技术社区：Hacker News、Reddit、GitHub Trending、Product Hunt。
- 科技媒体：TechCrunch AI、VentureBeat AI。
- 学术论文：arXiv 的 AI、计算语言学和机器学习分类。
- 官方渠道：Qwen 官方博客、DeepSeek 官方更新日志。

2026-08-20 的真实采集结果是：5 个正常、1 个可连接但暂无返回、3 个失败。页面上的“信源可用 5/9”是本轮真实状态，不代表永久状态。

## 2. 九个信源明细

| 信源 | 类型 | 入口 | 主要价值 | 2026-08-20 状态 |
|---|---|---|---|---|
| Hacker News | 社区 | Algolia `search_by_date` API | 高热度技术新闻和开发者讨论 | 正常，25 条 |
| TechCrunch | RSS 媒体 | AI 分类 RSS | 产品、融资、公司和行业新闻 | 正常，12 条 |
| VentureBeat | RSS 媒体 | AI 分类 RSS | 企业 AI、模型和产业动态 | 正常，7 条 |
| Reddit | 社区 | `r/MachineLearning`、`r/artificial`、`r/LocalLLaMA` | 社区讨论、开源模型和实践反馈 | 超时失败 |
| arXiv | 学术 | `cs.AI`、`cs.CL`、`cs.LG` RSS | 论文和前沿研究 | 正常，15 条 |
| GitHub Trending | 社区 | 全站和 Python 日榜 | 热门 AI 开源项目与工具 | 超时失败 |
| Product Hunt | 社区 | RSS，失败后尝试 HTML | 新 AI 产品和工具 | HTTP 403 |
| Qwen Blog | 官方 | `https://qwen.ai/blog` | Qwen 官方发布 | 可连接，暂无可解析条目 |
| DeepSeek Updates | 官方 | DeepSeek API 文档更新页 | DeepSeek 官方更新 | 正常，5 条 |

健康状态含义：

| 状态 | 含义 |
|---|---|
| `ok` | 成功请求并返回了内容 |
| `partial` | 一个信源包含多个入口，部分失败但仍取得内容 |
| `failed` | 请求失败或适配器异常，没有取得内容 |
| `empty` | 网络请求成功，但当前没有解析到内容 |

## 3. 信源不是同等可信

程序将信源分为四种类型：

| 类型 | 示例 | 当前候选评分加成 |
|---|---|---|
| `official` | Qwen、DeepSeek | +3 |
| `rss` | TechCrunch、VentureBeat | +2 |
| `academic` | arXiv | +1 |
| `community` | HN、Reddit、GitHub、Product Hunt | +1 |

这只是候选排序加成，不表示官方内容一定重要，也不表示社区内容不可信。最终仍需要结合事件本身和原始链接判断。

## 4. 信息进入实时池前经过什么处理

```text
原始抓取
  -> URL 精确去重
  -> 标题相似度去重（相似度 > 85%）
  -> 信源质量门槛
  -> 上海时区自然日过滤
  -> 营销和垃圾关键词过滤
  -> 主题分类
  -> A/B/C 程序初筛
  -> 与当天已有信息池合并
```

社区信源的最低热度门槛：

| 信源 | 最低 points |
|---|---:|
| Hacker News | 10 |
| Reddit | 5 |
| Product Hunt | 10 |
| GitHub | 20 |

arXiv、媒体 RSS 和官方信源不使用热度门槛。

## 5. A/B/C 初筛如何计算

A/B/C 是 `collector.py` 的程序规则，不是 GPT 的最终结论。

### 5.1 热度分

| 热度 | 加分 |
|---|---:|
| `points >= 200` | +3 |
| `points >= 100` | +2 |
| `points >= 50` | +1 |
| 其他 | +0 |

### 5.2 信源分

- Hacker News、Qwen、DeepSeek、arXiv：+1。
- `source_type == official`：额外 +2。

### 5.3 关键词分

重大关键词每命中一个 +2，例如：

```text
release, launch, announce, breakthrough, 发布, 开源,
funding, 融资, acquisition, 收购, CEO, CTO,
billion, SOTA, first, 首次, official, 正式
```

实用型关键词每命中一个 +1，例如：

```text
update, 更新, new feature, beta, preview,
benchmark, comparison, tutorial, 教程,
best practice, case study
```

### 5.4 等级阈值

| 条件 | 初筛等级 |
|---|---|
| 总分 >= 5，或重大关键词命中 >= 2 | A |
| 总分 >= 2 | B |
| 其他 | C |

例子：一条官方“新模型正式发布”信息可能获得官方加分，并命中“新模型发布”类重大关键词，因此容易进入 A 级。普通教程可能只命中实用关键词，因此更可能是 B 级。

## 6. 为什么还有第二次候选评分

A/B/C 只能快速粗筛。次日结算时，程序会计算更细的候选分，决定哪些内容值得发送给 GPT。

候选分由以下部分相加：

| 项目 | 分数 |
|---|---:|
| A/B/C 基础分 | A +7，B +4，C +1 |
| 信源类型 | 官方 +3，RSS +2，学术 +1，社区 +1 |
| 热度 | 按数量级增加，最多 +3 |
| 有摘要 | +1 |
| 有原始链接 | +1 |
| 有发布时间 | +1 |
| 命中高影响词 | +2 |
| 命中开发者价值词 | +1 |
| 命中主要 AI 机构 | +3 |

规则还会：

- 排除与 AI 主题无关的内容。
- 对同 URL、标题高度相似或关键词高度重合的事件再次去重。
- 只保留候选分至少 7 分的内容。
- 最多选择 24 条候选。
- 基础配额为学术 8、社区 10、官方 4、RSS 8。
- 候选分达到 10 的重大事件可以在配额后回补，降低漏报风险。

候选分只负责“选谁进入模型”，不直接成为用户看到的星级。

## 7. 日报里的 1～5 星如何产生

当前真实实现是：

1. 程序把候选事件、A/B/C 初筛级别、候选分、热度、来源、发布时间和链接发给模型。
2. Prompt 要求模型为每条重要事件输出“推荐指数（⭐1-5个）”。
3. 模型结合“行业影响、对开发者价值、事件新颖性”等语义自行决定星数。

重要说明：

> 当前代码没有把 1～5 星定义成可复算的固定公式，也没有校验星数与 A/B/C 是否一致。

因此现在的星级属于“AI 编辑推荐”，不是客观测量值，也不是简单由热度换算。相似事件在不同日报里可能出现尺度偏差。

### 未来建议的统一星级标准（尚未实现）

| 星级 | 建议含义 |
|---|---|
| 1 星 | 相关但影响有限，快速浏览即可 |
| 2 星 | 有参考价值，适合关注特定领域的人 |
| 3 星 | 对 AI 应用开发者有明确行动价值 |
| 4 星 | 重要模型、产品或基础设施变化，影响较广 |
| 5 星 | 可能改变行业方向、成本结构或主流开发方式 |

正式实现前需要用户确认，因为这会修改 Prompt 和日报质量规则。

## 8. 日期对评分的影响

次日结算只保留 `published_at` 明确属于目标日期的事件：

```text
target_date = 2026-08-19
只允许 2026-08-19 00:00:00 至 23:59:59（Asia/Shanghai）
```

当前 GitHub、Product Hunt、Qwen 和 DeepSeek 适配器可能返回空发布时间。这些内容可以暂存在今天的实时池，但会被严格的最终日报日期过滤排除。

这是当前最重要的数据覆盖缺口之一：来源可能抓到了，但因为无法证明它属于目标日期，最终日报不能安全采用。

## 9. 如何验收评分和来源

### 查看实时池

打开：

```text
data/realtime/YYYY-MM-DD.json
```

重点检查每条信息的：

- `source`
- `source_type`
- `published_at`
- `link`
- `points`
- `category`
- `importance`

### 查看信源健康度

```powershell
python src/collector.py --test-sources
```

或执行一次详细采集：

```powershell
python src/collector.py --verbose
```

### 查看进入模型的候选依据

候选文本中会带有：规则初筛级别、规则分、热度、信源、发布时间和原始链接。自动测试覆盖候选去重、来源配额、高价值回补和可追溯字段。

## 10. 如何正确理解最终日报

- 原始来源和发布时间是事实字段。
- A/B/C 是程序规则初筛。
- 候选分是程序排序工具。
- 1～5 星是当前模型的编辑推荐。
- GPT 的“影响分析”和“普通人可以做什么”属于 AI 分析，不应被当作已经证实的事实。
- 重要结论应点击原始链接复核。
