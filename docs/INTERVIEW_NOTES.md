# AI 信息雷达面试讲解材料

## Batch 1：自动更新与日报连续性自愈

### 为什么优化

系统虽然有采集器、日报脚本和计划任务，但真实检查发现计划任务根本没有注册，日报也缺了多天。也就是说“代码看起来有自动化”不等于“产品真的每天自动更新”。

### 优化前

- 首页只检查昨日日报。
- 旧日期失败后不会自动进入恢复队列。
- 陈旧锁会长期留在磁盘。
- 安装脚本遇到拒绝访问仍打印“已注册”。
- 任务绑定到 Codex 临时 Python，未来可能失效。
- AI 把原始链接少写一个词时，整份日报失败。

### 优化后

- 系统知道从首期到昨天应有多少期、完成多少期、缺多少期。
- 昨天优先，其余缺口按日期补；一次只处理一期。
- 文件锁保证同一日期只有一个模型调用。
- 自动失败最多 4 次，每次间隔至少 15 分钟。
- 安装失败直接报错；解释器必须长期存在且依赖完整。
- 可确定的同域名链接小误差被修复回原始候选 URL，未知链接仍被拒绝。

### 数据流

```text
计划任务触发
  -> 扫描 daily/realtime/update_status
  -> 计算 continuity
  -> 选择 pending target_date
  -> 原子创建 target_date.lock
  -> 读取该日信息池
  -> 规则过滤和事件去重
  -> 单次 AI 调用
  -> 链接归一化 + 质量校验
  -> 临时文件原子替换正式日报
  -> 状态 success / failed
  -> 首页与 API 展示结果
```

### 技术难点与 Debug

1. **假成功**：PowerShell 的部分错误是非终止错误，脚本继续执行并打印成功。解决：`$ErrorActionPreference = 'Stop'`，注册后反查任务。
2. **错误解释器**：Codex 环境中的 `python` 排在 PATH 最前，但不适合长期任务。解决：过滤临时路径，逐个执行 `import flask, markdown`，选中稳定 Python。
3. **并发与费用**：刷新和计划任务可能同时触发。解决：用 `O_CREAT | O_EXCL` 原子文件锁，日期成为幂等键。
4. **失败风暴**：网络或模型失败可能重复付费。解决：持久化 `attempt_count`，自动重试限 4 次并加冷却。
5. **质量闸门误杀**：模型把 TechCrunch slug 少写一个词。解决：只允许同域名、唯一且路径相似度 ≥ 0.88 的链接恢复到候选原链接。

## 30 秒版本

我做了一个 AI 行业情报系统，核心不是简单抓新闻，而是全天低成本采集、次日规则筛选后只调用一次模型生成日报。一次真实体检发现，计划任务并未生效，历史缺口也不会恢复。我设计了日期级连续性扫描、原子文件锁、单期恢复队列和限次重试，并修复了 PowerShell 安装脚本“失败却显示成功”和临时 Python 路径问题。最终 37 项测试通过，真实采集 6/9 个信源成功，AI 质量闸门修复后真实生成了一期 7946 字符日报。

## 2 分钟版本

项目原来已经有采集、Flask 展示和 AI 日报，但我没有只看代码，而是检查运行数据和 Windows 计划任务。结果发现从首期到昨天应有 26 期，只有 17 期；两个计划任务都不存在，还有一个日期锁陈旧了几天。所以最大问题是“自动化假闭环”。

我先建立 continuity：把日报分成已完成、可用现有信息池恢复、缺少信息池、运行中和失败。任务选择策略是昨天优先，其余按最早缺口，每次只处理一期。计划任务、首页按钮和命令行都复用同一个日期级原子文件锁，避免一次刷新一次模型调用。失败状态持久化，自动最多 4 次并有 15 分钟冷却，手动仍可重试。

真实部署时又发现两个工程问题：PowerShell 遇到拒绝访问仍打印成功；任务还绑定到了 Codex 临时 Python。我让脚本失败即退出、注册后反查任务，并排除临时解释器，实际导入 Flask 和 Markdown 后选择稳定 Python。

最后做了真实验收：采集任务成功，9 个信源有 6 个可用；AI 第一次因为模型拼错来源链接被质量闸门拦截，我增加严格的同域名唯一高相似 URL 归一化，第二次成功生成日报。这个过程体现了任务幂等、故障恢复、数据质量保护和真实环境 Debug。

## 深挖问答

### 为什么不用数据库或 Redis 锁？

当前是单机、低并发、按天生成，文件系统的原子 `O_EXCL` 已能保证跨进程互斥。引入 Redis 会增加部署和故障点。重新评估条件是多机部署或同一任务需要分布式执行。

### 为什么先规则筛选再用 GPT？

采集到的原始文章中有重复、低价值和非 AI 内容。程序先做确定性过滤、日期隔离、配额和候选分，把候选控制在 24 条以内；GPT 只做真正需要语义理解的排序和分析，降低 Token 与幻觉风险。

### 如何保证失败不破坏历史日报？

AI 输出先在内存中完成链接修复和质量校验，通过后写临时文件，再用原子替换写入正式路径。任何网络、解析或质量错误都会把任务标记 failed，但旧日报不会删除或覆盖。

### 为什么没有直接补齐缺少信息池的日期？

RSS 通常只能返回最新内容，用今天的数据补历史日报会造成日期污染。系统只自动恢复已有且日期匹配的信息池；无历史查询能力的来源不能伪造回溯数据。这是数据正确性高于“表面无缺口”。

### 下一步为什么是 Event？

当前 URL 和标题相似度只能在候选阶段临时去重，无法把多篇文章永久表示成一个真实事件。建立 Article/Event 契约后，才能稳定保留多来源证据、统一重要性分数，并为未来搜索、RAG 或 Research Agent 提供可靠输入。
