# AI 信息雷达项目指南

> 面向第一次接触本项目的人。当前代码基线：v1.15，日期：2026-08-20。

## 1. 项目解决什么问题

AI 信息雷达帮助 AI 应用开发者每天完成三件事：

1. 持续收集当天公开 AI 信息。
2. 从大量信息中筛出值得关注的候选事件。
3. 在第二天生成前一天的完整 AI 日报。

项目追求的不是“新闻最多”，而是：

> 在来源可追溯、日期不混乱、成本可控制的前提下，让用户更快看懂真正重要的 AI 变化。

## 2. 两个最重要的产品概念

### today_realtime

今天正在变化的信息池。例如 2026-08-20 白天采集到的内容进入：

```text
data/realtime/2026-08-20.json
```

它会随全天采集不断追加，不是最终日报。

### daily_report

已经结束自然日的稳定日报。例如 2026-08-20 00:05 结算 2026-08-19：

```text
data/daily/2026-08-19.md
```

今天的数据不能提前成为今天的最终日报。

## 3. 一张图看懂系统

```text
9 个公开信源
    |
    | 每 2 小时，程序采集，不调用大模型
    v
去重 -> 质量过滤 -> 日期过滤 -> 垃圾过滤 -> 分类 -> A/B/C 初筛
    |
    v
data/realtime/YYYY-MM-DD.json
    |
    | 次日 00:05，目标日期固定为昨天
    v
严格日期隔离 -> AI 相关性过滤 -> 事件去重 -> 候选评分 -> 最多 24 条
    |
    v
OpenAI Responses API -> GPT 生成 Markdown -> 输出质量校验
    |
    v
data/daily/YYYY-MM-DD.md
    |
    v
Flask 首页 / 日报详情 / API / 已读状态
```

更详细的数据流见 [daily-workflow.md](daily-workflow.md)。

## 4. 主要模块

| 模块 | 文件 | 主要职责 |
|---|---|---|
| Web 应用 | `src/app.py` | 首页、详情页、API、已读状态、日报更新状态 |
| 采集器 | `src/collector.py` | 并发采集、过滤、分类、初筛评分、写入实时池 |
| 信源适配器 | `src/sources/` | 把不同网站的数据转换为统一 `NewsItem` |
| 日报生成器 | `src/generate_daily.py` | 日期隔离、候选筛选、模型调用、输出校验、日报写入 |
| 页面 | `src/templates/` | Jinja 模板 |
| 样式与图标 | `src/static/` | 页面样式和雷达图标 |
| 计划任务 | `tools/setup_schedule.ps1` | 注册全天采集和次日结算任务 |
| 启动器 | `tools/start_source.ps1` | 确保打开的是主源码实例，而不是旧 EXE |
| 测试 | `tests/` | 日期、锁、质量、信源、API 等回归测试 |

## 5. 数据存在哪里

本项目当前没有数据库服务器，主要使用本地文件。

| 路径 | 内容 | 是否可删除 |
|---|---|---|
| `data/realtime/YYYY-MM-DD.json` | 当天实时信息池 | 不应随意删除 |
| `data/daily/YYYY-MM-DD.md` | 已完成日报 | 不应删除或跨日期覆盖 |
| `data/update_status/` | 日报任务状态和日期锁 | 运行数据，不提交 Git |
| `data/read_status.json` | 电脑端已读记录 | 不应随意覆盖 |
| `data/logs/` | 采集、结算、服务日志 | 可按维护规则归档 |
| `data/raw/` | 旧流程或手动模式的素材 | 使用前先确认对应流程 |

关键日期字段：

| 字段 | 含义 |
|---|---|
| `published_at` | 信息在原网站实际发布的时间 |
| `collected_at` | 本系统抓到信息的时间 |
| `collect_date` | 实时信息池所属自然日 |
| `report_date` | 最终日报所属自然日 |

日报归属必须由 `published_at` 决定，不能用文件修改时间或采集时间代替。

## 6. 用户打开首页时发生什么

```text
用户访问 127.0.0.1:8899
    |
    v
Flask 读取 data/daily 中最近完成的日报
    |
    +--> 读取今天 realtime JSON，展示采集条数和信源健康度
    |
    +--> 读取昨天的结算状态
    |
    v
立即返回首页，不等待采集或 GPT
```

“刷新 / 检查更新”主要检查昨日日报状态。它不会每点一次就重新采集或调用一次模型。

## 7. 当前 API

| 方法 | 地址 | 用途 |
|---|---|---|
| GET | `/` | 首页 |
| GET | `/daily/<YYYY-MM-DD>` | 日报详情，并记录已读 |
| GET | `/api/reports` | 返回全部日报，供同步使用 |
| POST | `/api/read/<YYYY-MM-DD>` | 同步某期已读状态 |
| GET | `/api/update-status` | 查询昨日日报四态状态 |
| POST | `/api/update-check` | 必要时启动一次后台结算 |
| GET | `/api/instance` | 确认 8899 是否为主源码实例 |

这些 API 当前主要用于个人电脑和局域网，没有完整用户认证系统，不应直接暴露到公网。

## 8. AI 调用

日报结算通过兼容 OpenAI Responses API 的端点调用模型：

```text
POST {OPENAI_BASE_URL}/responses
```

配置来自用户环境变量：

- `OPENAI_API_KEY`：必填，真实密钥只能放在环境变量。
- `OPENAI_BASE_URL`：当前默认 `https://stariver.top/v1`。
- `OPENAI_MODEL`：可选，当前默认 `gpt-5.6-luna`。

采集阶段不调用模型。正常情况下，一个自然日的最终日报只进行一次模型生成；失败重试可能再次调用。

## 9. 当前已经具备的保护

- 上海时区自然日隔离。
- 同一日期的跨进程任务锁。
- 采集和 AI 分离。
- 单个信源失败不拖垮其他信源。
- 实时池原子写入。
- 日报写入前检查日期、章节、长度和重要事件链接。
- AI 失败不覆盖旧日报。
- 首页不等待后台任务。
- 主源码实例身份检查，避免打开旧 EXE。

## 10. 当前已知限制

1. GitHub、Reddit、ProductHunt 在 2026-08-20 的真实采集中仍受超时或 403 限制。
2. GitHub、ProductHunt、Qwen 和 DeepSeek 适配器目前可能缺少可靠 `published_at`；严格结算会排除无法确认日期的内容。
3. 日报中的 1～5 星目前由模型判断，没有程序化统一公式。
4. 采集器使用关键词和规则评分，可能有误判或漏判。
5. 当前没有完整 Token、模型耗时和日报命中质量看板。
6. 当前目录尚未初始化 Git 仓库，正式开源前需要建立版本基线。

## 12. 常用术语

| 术语 | 小白解释 |
|---|---|
| 信源 | 新闻或信息来自哪个网站、社区或官方页面 |
| 适配器 | 把不同网站格式转换成项目统一数据格式的小程序 |
| RSS | 网站提供的结构化更新订阅格式 |
| API | 程序之间交换数据的接口 |
| 去重 | 识别多个来源报道的同一事件，只保留一个候选 |
| 候选事件 | 程序筛选后、准备交给 GPT 深度分析的信息 |
| 原子写入 | 先写临时文件，完整成功后再替换，避免留下半个文件 |
| 任务锁 | 防止同一天被多个进程同时生成多次日报 |
| 回归测试 | 修改后确认旧功能仍然正常的测试 |
